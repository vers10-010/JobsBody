Включаем корневые текстовые правила и указатели, jobsbody_paths.py и Introduction_status.json; текстовые файлы журналов; текст, данные и код outputs/Third_Edition_Reader_2026-10-30; исходные сценарии и текстовые результаты work/third_edition_reader_2026-10-30 и work/third_edition_coverage_2026-10-30. Общие инструкции.md содержит точный текст C:\Users\vers1\.codex\AGENTS.md с указанием источника. Этот файл — локальная копия правил для истории проекта; автоматическое чтение произвольного имени или синхронизация с глобальным файлом не настроены. Проектный AGENTS.md остаётся действующим источником правил книги.

Пока исключаем прежние выпуски outputs, прежние рабочие каталоги work, Объединение, Материалы из прежних папок, Git-план, Вложения, source_photos, output, tmp, временные папки Drive. Это ограниченный старт репозитория JobsBody, а не учёт всех его материалов. При расширении состава сначала изменить .gitignore и проверить список добавляемых файлов.

В разрешённых каталогах учитываются текстовые форматы md, txt, json, jsonl, html, css, js, cjs, py, cmd, bat, ps1, csv, tsv. Изображения, аудио, видео, архивы, PDF, DOCX, XLSX, модели и двоичные библиотеки не включаются. Папки зависимостей runtime, node_modules, .venv, venv, __pycache__, _build, а также tts_parts, audio и originals исключены. Текстовые файлы неизвестного расширения тоже пока не учитываются. Проверка имён не является полной проверкой содержимого на пароли; перед первым коммитом просмотреть выбранные тексты.

Исключение из Git не удаляет файлы. Git с этим составом не является полной резервной копией книги: клон репозитория без оставшихся на диске аудио и фотографий не будет полноценным озвученным ридером. Журнал хранит подтверждение прослушивания; localStorage браузера в Git не входит.

## Создание в GitHub Desktop

1. Открыть GitHub Desktop. File → New repository… (Ctrl+N).
2. Name: JobsBody. Local path: C:\Work. Итоговый путь должен быть C:\Work\JobsBody, без второй вложенной папки JobsBody.
3. Description можно оставить пустым. Initialize this repository with a README — не отмечать. Git ignore: None. License: None. Существующий .gitignore уже подготовлен.
4. Проверить путь внизу диалога. Create repository создаёт служебную папку .git в текущем проекте, не перемещая рабочие материалы. Если приложение сообщает о конфликте или предлагает другой путь, остановиться и передать точный текст сообщения.
5. После создания сообщить Codex: «репозиторий создан». До первого коммита проверить через чтение Git корень, список файлов и исключения. Нельзя объявлять репозиторий созданным только по наличию этого руководства.
6. В Changes просмотреть список файлов и изменения. Ожидаются десятки текстовых файлов, а не десятки тысяч библиотек. Если видны аудио, фотографии, runtime или прежние выпуски, сначала исправить состав.
7. Если Desktop уже создал Initial commit, просмотреть его в History: важны не имя и количество коммитов, а фактический состав.
8. Для ещё не сохранённых изменений написать Summary: «Начальное состояние JobsBody: правила, журналы и ридер третьего издания». Нажать Commit to main (или название фактической текущей ветки). Это запись локальной версии.
9. Publish repository не нажимать. Удалённое хранилище не добавлять.

## Дальнейшие изменения

Changes показывает сохранённые на диске изменения после предыдущего коммита. Выбрать файлы, прочитать разницу, заполнить Summary и нажать Commit to текущая ветка. History показывает сохранённые версии. Для крупной новой функции можно создать отдельную ветку, сохраняя основную версию.

Перед изменением файлов Codex продолжает уведомлять о путях, цели и отмене. В конце работы проверяет фактический список Git; создание коммита обсуждается в рамках текущего поручения. Discard changes меняет рабочие файлы: это не кнопка закрытия просмотра.

Первая версия фиксирует нынешнее состояние. Старые этапы автоматически не восстанавливаются как коммиты; в первом составе есть две сохранённые HTML-версии и журнал хода исправлений. Не следует восстанавливать их поверх текущего ридера ради искусственной истории без отдельного поручения.
